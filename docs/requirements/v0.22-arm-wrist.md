# v0.22：第一人称手腕扭曲修正

- **状态**：已上线（v0.22，2026-11-09）
- **分支**：`v0.22-arm-wrist`
- **开始**：2026-11-09　**完成**：2026-11-09

## 需求

负责人用开发者模式录了一段（上传编号 `20261109-134638-0e1c64`，Apple M3、Chrome、120Hz、M4 + SG 手枪），
问："PC 的手和臂之间的连接，是不是有点扭曲？" 确认后要求"按分析出来的最优方式进行修正"。

## 范围

- 做：第一人称手臂的解算（`gunmodel.js` 的 `buildArms().solve`），所有枪和投掷物共用。
- 不做：不改手的握持位置和朝向（`Weapon.VIEW` 不动），不改手臂模型和贴图，不改第三人称角色的手臂。

## 分析

- 录像第 45 秒附近放大看左手：小臂是一根直圆柱，到手套口手突然折上去托护木；手套口一圈皮肤往里收、发红，是蒙皮大角度弯折挤瘪的样子。
- 量出来（相对蒙皮绑定姿势）：M4 左手腕弯 55°、扭 17°，右手腕弯 55°；SG 左手腕弯 60°、扭 13°。手肘 0°。
- 原因：手的朝向由握持点决定；小臂和上臂不管手朝哪，直接沿 `armDir` 伸出画面，手肘不弯，两者的夹角全压在手腕上。
  小臂绕自身的扭转是按掌心法线投影出来的，弯得越大偏得越多，于是还带扭转。
- 另外发现：`arm.glb` 场景里的默认姿势和蒙皮绑定姿势不一样，左手腕在默认姿势里已经相对绑定姿势扭了约 30°。
  蒙皮按绑定姿势变形，所以"没弯"的基准必须用绑定姿势。

## 方案和决定

- 小臂方向：先算"手腕相对绑定姿势不弯"时小臂的方向，再往 `armDir` 转，转到手腕弯折达到上限 `wristMaxBend`（20°）为止；
  剩下的角度交给手肘，上臂继续沿 `armDir` 伸出画面（肩膀位置跟着变，在画面外）。
  20° 是正常端枪时手腕的弯折量；比它小，手肘要弯得更多，小臂在画面里占的地方更大。
- 小臂、上臂的旋转 = "不弯时的朝向"再加一个最小摆动（`setFromUnitVectors`），不绕自身转，所以手腕只有弯折、没有扭转。
- 基准姿势从 `skeleton.boneInverses` 取（`measureArms` 的 `bindEW` / `bindSE`），骨骼长轴用子骨骼的局部位置（`foreAxis` / `upperAxis`）。
- 考虑过：把 `armDir` 逐把枪手调到和手掌对齐。没选：每把枪、每个动作都要调，而且换弹时手动了又会偏。

## 验证

- `/verify`：问题 0。
- `tools/tests/arm-wrist.mjs`：M4 / SG / AK / Beretta 平时和换弹中、三种投掷物，手腕弯折都是 20°、扭转 0°，手肘弯 22°～40°，全部通过。
- `tools/tests/reload-nade-economy.mjs`：全部通过。
- 截图（改前 / 改后对比，正视和侧视）：手的握点不变；手腕从折角变成顺着小臂延伸，弯折移到手肘；
  步枪的左小臂改成从左边更平地伸进来，手枪双臂的手肘略向外撑。

## 遗留

- 手套口那圈发红可能有一部分是贴图本身（改后弯折小了，挤瘪没了，但颜色还在），要真机录一段再看。
- 真实画面和手感要负责人在有显卡的电脑上看；觉得小臂位置不顺眼可以调 `wristMaxBend` 或 `Weapon.VIEW` 的 `armDir`。
