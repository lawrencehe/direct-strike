# v0.21：开发者模式（录制真机数据和画面，上传给开发分析）

- **状态**：已上线（v0.21，2026-11-09）
- **分支**：`v0.21-dev-mode`
- **开始**：2026-11-09　**完成**：2026-11-09

## 需求

开发机没有显卡，开发时只能看到逐帧截图，看不到连续动作，负责人实际试玩时经常发现动画和手感不合理。
要让开发看到的东西和负责人真机上的体验尽量一致。负责人的要点（2026-11-09）：

- 设置里有"开发者模式"，打开后游戏运行时持续生成数据，在开发者模式里能看到；点"上传"把数据传到本机服务器的某个目录。
- 打开开发者模式**不能让游戏变卡**；数据不必实时落盘。
- 除了数据还要**录画面**。视频切片存，不要一大坨；分辨率和码率不用太高（由开发定）。
- 开发者模式不能谁都能开：**输入固定密码，服务器校验通过才能打开**。
- 服务器磁盘充足，数据目录上限 **10 GB**。
- 以后要做后台管理系统（玩家登录、数据管理），在服务器上给指定玩家开开发者模式。这次不做，但接口要按这个方向留好。

## 范围

- 做：
  - 游戏里：每帧录数据（真实帧间隔、输入、玩家、武器状态、枪模和左手的实际位置）进内存环形缓冲；按键打标记；
    战斗中的小浮层（帧率、帧时间曲线、录制状态）；设置里的"开发者"栏（密码解锁、开关、统计、上传、下载）。
  - 录画面：可选开关，默认关，缩小后录成 5 秒一片的 webm，内存里滚动保留最近几片，上传时一起传。
  - 服务器：一个只给开发用的小接口服务（密码换令牌、接收上传、目录配额），线上和本地 `start.sh` 用同一个脚本。
  - 开发这边：分析脚本，输出帧时间统计、卡顿、标记前后的曲线图和视频帧。
- 不做：
  - 后台管理系统、玩家账号、按玩家开权限（以后单独做）。
  - 用录下来的输入在本机复现回放（要求游戏随机数可固定，以后再说）。
  - 实时调参滑块（另提需求）。
  - 浮层、开发者面板之外的界面改动；玩法不动。

## 方案和决定

- **为什么不是给开发机加 GPU**：动画和手感的问题主要是"开发只看得到单张截图"，加了 GPU 也看不到负责人的显示器刷新率和真实手感，
  而且这台机器上还跑着线上站点和 relay，换机型要停机。所以把负责人真机上的每帧数据录下来，开发画成曲线看。
- **只录战斗中的帧**（鼠标锁定时）：暂停下来看面板、上传，不会把战斗数据挤出 60 秒的缓冲。
- **不影响性能**：每帧只往预分配的 `Float32Array` 写数字，零分配（测试里用 CDP 采样堆分析器确认 2 万帧 0 字节）；
  按键位掩码在键盘事件里算好；浮层 4Hz 刷新；整理、压缩、上传只在点按钮时做。开发机上 `sample()` 约 10µs/帧。
- **事件从状态变化推出来**（开火 = 子弹变少，换弹开始 / 结束，切枪，落地……），不改武器和玩家的代码，只在 `main.js` 挂两个调用。
- **录画面**：960 宽、30fps、1.5Mbps 的 webm，每 5 秒换一个录制器，每片都能单独播放，内存里留 6 片（30 秒）。
  渲染后立刻把 WebGL 画布缩小拷到 2D 画布，`captureStream(30)` 自动采样。手动 `requestFrame` 的写法在无头环境录出来是空的，不用。
- **录画面的保护**：无头 Chromium + 软件渲染下录 WebGL 画面会卡住整个页面出帧（开发机上复现了，直接录 WebGL 画布也一样）。
  有显卡的 Chrome 里这是常规做法，但这里验证不了，所以默认关，并且出现超过 1 秒的帧、2 秒内 3 帧超过 0.2 秒、
  或者战斗中 1.5 秒没出帧（用定时器查，出帧停了每帧的检查跑不到）就自动关掉并提示。
- **服务器**：`server/api.py`，只用 Python 标准库，本地 `start.sh` 和线上 `fps-api` 容器同一份。
  线上 `fps-game` 的 Caddy 把 `/api/*` 转给 `fps-api`，**relay 的 Caddyfile 不动**。接口代码 rsync 到 `/home/donkey/fps-api` 再挂进容器，
  不挂仓库目录。密码在 `~/direct-strike-data/api.env`（首次部署自动生成，不进仓库）。
- **令牌**：`base64(JSON {sub, exp}).HMAC`，钥匙由 `API_SECRET` + 密码算出，改密码旧令牌全部失效；30 天有效。
  `sub` 现在固定 `dev`，以后的后台换成玩家 id 就能按人授权。登录按 IP 限流（10 分钟 10 次）。
- **分析脚本**用 Playwright 自带的 Chromium 画图和拆视频帧，不另装 ffmpeg。MediaRecorder 的 webm 没有索引、跳转不准，
  所以顺序播放，用 `requestVideoFrameCallback` 给每个目标时刻留最近的一帧。`file://` 视频画到 canvas 上算跨源，启动参数加 `--allow-file-access-from-files`。
- **Caddyfile 单文件挂载会过期**（git 切分支换了文件，容器里还是旧的），`deploy.sh` 发现不一致就重建 fps-game。
