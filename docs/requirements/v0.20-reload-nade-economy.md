## 需求

负责人原话（2026-11-09）：

1. 换弹时，出现换弹中...文字，这个视觉效果比较差，可以做一些改进，如果没有更好的动画方案，可以把文字去除，完善整个换弹的动作。
2. 据我所知，手雷的爆炸原理是这样的：两个保险，一是引信，二是握把，引信拉开后，只要不松握把，那么手雷是永远不可能开始倒计时并爆炸。如果这个逻辑属实，可以按照这个逻辑来修正手雷在游戏中的运行逻辑。
3. 现在游戏，无论我打死多少人，我的手雷都没有补充，我觉得可以引入经济系统，即当我打人打死后，我回到我的出生点，我就可以重新采购，而我的金钱数量取决于打死的敌人数，爆头/普通击中打死（只认最后一枪）/手雷炸死，都是不同的金钱收入，收入定个上限。

中途补充（同一天）：

4. 弹药打光后，我应该自动就开始换弹的动画，而不是等到我击发时换弹，如果此时我切枪，换弹中止。

关于第 2 条：原理属实。真实手雷（如 M67）拔掉保险销后，保险握片（spoon）被手压着，击针就打不下去；
松手握片弹开，引信才开始燃烧。所以照这个逻辑改了。

## 范围

- 做：
  - 换弹：去掉文字，重做完整换弹动作和分段音效；弹药数下加进度细线；打空自动换弹，切枪中止，切回空枪自动再换。
  - 手雷：拔环后攥着不计时，出手才计时，手上不会炸。闪光弹、烟雾弹同样处理。
  - 经济：赏金（按最后一击分三种）、钱的上限、出生点购买区、购买面板、购买投掷物。只在对决和波次里有。
- 不做：
  - NPC 经济（NPC 照旧每条命满装备）。
  - 卖枪、卖子弹（子弹本来就无限）、卖血或护甲：负责人只提了补充投掷物，不擅自扩展玩法。
  - 训练场经济（投掷物不限量）。
  - 主动"捏雷"（故意先松握片再丢）：新规则下没有这个操作，负责人要再说。

## 方案和决定

### 换弹

- 动作按换弹进度 p（0 ~ 1）分段，写在 `weapon.js` 的 `Weapon.RELOAD`：枪身侧倾抬起 → 左手抓弹匣 → 弹匣抽出（加速，像甩掉）→
  左手往下离开画面拿新弹匣 → 托着新弹匣插回、枪身震一下（拍实）→ 回位。**空枪**换弹最后多一段拉机柄 / 套筒到底再放开（上膛）。
  `Weapon.reloadPose(p, empty)` 把进度换算成各个动作的量，`animate` 叠到枪、弹匣、左手、机柄上。
- 空枪和非空枪**总时长一样**（还是 `reloadTime`），空枪把前面压缩，腾出最后一段拉机柄。没有给空枪加时间：NPC 用的是同一个 `reloadTime`，加了就不对等了。
- 音效按 `cues` 到点才响（抽弹匣、插弹匣、拉机柄、放机柄）。原来是开始换弹时用 `audio.reload(time)` 把两声提前排好，中途切枪尾音照样响，这次一并修掉。
- 进度：不在准星旁写字，右下角弹药数变暗，下面一条橙色细线走满（`hud.setReload`）。考虑过准星周围画圆环，没选：准星附近要干净，看动作就够了，细线只告诉你还要多久。
- 自动换弹：打空后等最后一发的后坐做完（`cooldown <= 0`）就开始，不用再扣扳机。切回一把空枪、掏好之后也自动开始。
- **踩过的坑**：第一版枪身回正比左手回护木晚，枪还歪着手已经回去，第一人称的袖子被拉得很长。改成 tilt 下降和 grab 下降同步，截图确认正常。已写进 `../architecture.md` 的"已知的坑"。
- 上膛只动机柄和枪身，右手没有真的去拉机柄（手臂 IK 现在只支持握在固定点上），见遗留。

### 手雷

- `throwState` 的 `'hold'` 阶段（拔了环、攥着握片）不计时，攥多久都行；松开左键进入 `'swing'`，出手瞬间握片弹开（"叮"一声），
  `grenades.throw(kind)` 带**满的** `fuse` 飞出去。飞出去的雷模型隐藏拉环和握片（`gunmodel.js` 里握片命名为 `spoon`）。
- 人被打死时手一松，雷掉在脚下，从这时开始算满的 `fuse`。
- 删掉：`cookT`、`hud.setCook` 和准星下方的倒计时条、`grenades.explodeInHand`（"攥满在手里炸"）。
- 攥着雷时不能切武器（原来就是这样），只能丢出去。没有"把环插回去"的操作。
- NPC 丢雷原来就是出手时才带满引信，不用改。

### 经济

- **赏金只看最后一击**（`bots.onPlayerKill(hit)` → `main.js` 换算）：`hit.explosion` → 手雷 $400；`hit.part === 'head'` → 爆头 $300；其余（身体、腿）→ $200。
  NPC 被自己的雷炸死（`hit.byBot`）不给钱。手枪和步枪不区分。
- **"收入上限"理解为钱的上限**：最多存 $2000，满了再杀不涨，飘字显示"钱已到上限"。
  另一种理解是"单次赏金封顶"，但三种赏金本来就是定值，封顶没有意义，所以按存款上限做。**待负责人确认**。
- 钱跟着整局走，死了不清零；开新一局清零，开局 $0（开局本来就各带 1 个投掷物）。
- **购买区**是这条命的出生点（`player.spawn`）周围 3 米，地上一圈橙色的环（对决里每次重生的点不一样，环跟着走）。
  环一开始就放进场景、平时透明度 0，避免中途第一次出现时编译材质卡一下。
- **购买面板**：在购买区按 B 打开，按投掷物自己的槽位键（3 / 4 / 5）买一个。不解锁鼠标（解锁会触发暂停），开着照样能走能看能开枪。
  走出购买区、阵亡、再按 B 都会关。`economy.update` 在帧循环里排在 `weapon.update` 前面，用 `input.consumeAction` 吃掉槽位键，所以不会切到那个投掷物。
- 价格和携带上限：手雷 $300 / 最多 2，闪光 $200 / 最多 2，烟雾 $300 / 最多 1。都是先定的值，负责人可以在 `config.js` 的 `economy` 里调。
- **投掷物补给**：死了重生回到开局数量（多买的随人一起没了，`weapon.refill(false)`）；波次之间补到开局数量但不收走多买的（`refill(true)`）。
- 以上影响方向的决定已写进 `../decisions.md`。

## 遗留

- **待负责人确认**："收入上限"按存款上限 $2000 做的；价格和携带上限是先定的值。
- 真实手感（换弹节奏、音效）要在有显卡的电脑上试玩，开发机帧率不可信。
- 上膛时右手没有真的去拉机柄 / 套筒，只有机柄和枪身在动；要做得先给手臂加"中途换握持点"的能力。
- 新规则下没有"捏雷"（先松握片再丢让它空爆），如果想要可以以后加一个操作。
- NPC 换弹没有动作（原来就没有），NPC 也没有经济。
