# 项目方向和决策记录

记录"为什么是现在这样"。新的决定追加到对应小节，写上日期。

## 项目方向

- **1v1 对战框架优先。**（2026-11-03）先把"我和一个 NPC 单挑"做扎实：地图、NPC 形象、手感。
  创意玩法由项目负责人自己加，其他人（包括 AI 助手）不要擅自扩展玩法，只做被要求的功能和必要的修复。
- **对决规则**：击杀后在远处重生，先到 10 杀获胜，参数在 `config.js` 的 `duel`。
- **地图主题**：工业集装箱堆场。
- **面向边做边学的开发者。** 代码注释、文档都用中文；结构上追求"改一个参数就能看到变化"，所以数值集中在 `config.js`。

## 技术选型

- **纯浏览器、零构建、无后端。** three.js r149，脚本按 `index.html` 的顺序直接加载，全局命名空间 `Game.*`。
  不引入打包工具和框架，打开文件就能读懂。
- **本地运行用 `start.sh`（python http.server）**，不支持双击 `index.html`：浏览器禁止 `file://` 加载 glb 模型。
  直接双击时 NPC 会退化成方块小人（BlockModel），游戏仍能玩。
- **资源只用 CC0 / MIT**，来源登记在 `assets/LICENSES.md`。贴图和音效尽量用代码生成（`textures.js`、`audio.js`），不增加下载体积。
- **枪模、手、手雷、卡车都用基础几何体拼**，贴图用 Canvas 画，方便改造型，不依赖外部模型。
- **NPC 死亡用自己写的 Verlet 布娃娃**（`ragdoll.js`），不引入物理引擎。
- **多地图按需加载**：每张地图的资源单独放，选了哪张才下载哪张，首次下载体积保持在"引擎 + 一张图"。

## 开发和部署

- **开发机**（2026-11-05）：GCP 实例 4 核 32G，x86_64，无 GPU、无显示器。WebGL 靠 SwiftShader 软件渲染，
  截图和报错可信，帧率不可信。真实帧率和手感要在有显卡的电脑上测。
- **暂不支持 Safari**，所以没有为测试租云 Mac。需要真实帧率时优先按小时开 GPU 主机，不包月。
- **工具链走命令行**（Playwright、gltf-transform、Blender 无头模式），Claude Code 通过 `.claude/skills/` 调用，见 `tools.md`。
- **线上**（2026-11-04）：https://game.lightup.host，跑在开发机上，借用 paseo-relay 项目的 Caddy 按域名分流。
  relay 是另一个在线服务，不能中断，所以游戏不单独占 80/443。细节见 `deploy.md`。
- **分支开发完一律并入 `main`，从 `main` 部署；分支不删除，保留历史**（2026-11-06），见 `workflow.md`。
  起因：v0.10、v0.11 都从功能分支部署过，线上一度比 `main` 新，从 `main` 部署就会回退。
