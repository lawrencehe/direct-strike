# 项目方向和决策记录

记录"为什么是现在这样"。新的决定追加到对应小节，写上日期。

## 项目方向

- **1v1 对战框架优先。**（2026-11-03）先把"我和一个 NPC 单挑"做扎实：地图、NPC 形象、手感。
  创意玩法由项目负责人自己加，其他人（包括 AI 助手）不要擅自扩展玩法，只做被要求的功能和必要的修复。
- **对决规则**：击杀后在离对方最远的出生点重生；为了不出生就被杀、留出买枪的时间（负责人要求，#97），出生点都有一人高的掩体，出生后有短暂的无敌，开枪就结束（`config.js` 的 `spawnProtect`）。
  默认先到 5 杀获胜（2026-11-06 从 10 杀改为 5 杀，10 杀一局太久），首页可选 3 / 5 / 10，参数在 `config.js` 的 `duel`。
- **地图主题**：工业集装箱堆场。风格是**生锈、破旧、有战损的战场**（2026-11-11 负责人定，#50）。
- **地图分实景和虚景，先换外观再改布局**（2026-11-11，负责人定，#50）：实景是场地内玩家能走到、能碰到的部分，要精细的模型和 PBR 材质；
  虚景是围栏外的远景，只要轮廓和光照对。把"骨架"（`maps/*.json` 里的布局、碰撞盒、点位）和"外观"（模型、材质）分开：
  第一阶段 yard 的布局一点不动，按 地面和环境光 → 集装箱、沙袋、水泥墩 → 小道具 → 远景 的顺序逐个换外观，每步先给负责人看图。
  素材 Claude 先从 Poly Haven / ambientCG / Sketchfab 找，负责人也在找，找到再商量换；体积先不设上限，画质优先。
  以后的新地图先走"负责人给俯视草图和参考照片 → Claude 搭白模给负责人看布局 → 换皮"，负责人自己在 Blender 里摆地图等以后需要再说。
- **按产品组织界面**（2026-11-08）：打开网页先到首页（不全屏）选模式、看地图、改设置，点"进入战斗"才全屏，
  经过作战简报再开打；Esc 暂停，打完有结算页。风格是军事写实，强调色用 logo 的橙色。先按本地对战做，
  账号、联机大厅、商店这类以后的功能暂不预留位置。细节见 `ui.md`。
- **装备做成可选的物料**：枪（主、副武器）和 NPC 形象列在 `config.js` 的 `loadout`，新模型加一项就能买到 / 被 NPC 随机到。
  目前换枪只换外观，数值相同（玩法由负责人定，要区分在 `loadout` 里写覆盖参数，#20）。
- **枪在局内买，首页不选装备，NPC 随机**（负责人定，#90）：进入战斗前只定模式、地图、天气和杀数。出生只有手枪，主武器在购买区买，死了掉；
  原则是**出生后一定能用上主武器**，所以开局 / 重生保底的钱够买主武器（`startMoney` ≥ 主武器价格），整局都能体验主武器，钱的差别体现在子弹和投掷物上。
  NPC 每次出生随机形象、随机一把主武器和一把手枪，**一定有主武器**（只有手枪太弱，不平衡）。赛制不变（先到 N 杀）。
  F 快捷购买必须纯键盘、放在屏幕左侧、买完就关——开菜单时敌人进攻不能丢了瞄准；B 菜单可以用鼠标，在安全的地方买。
  套餐里的主武器不预设型号：有就不换，没有买上次买的那把。
  模型可能来自朋友制作，没有原作链接，登记规则见 `assets/LICENSES.md`。
  暂未接入：锯短霰弹枪（自带手臂和动画，要新增霰弹玩法）、`russian_soldier.glb`（没有骨骼，要先绑定）。
- **手雷按真实的两道保险**（2026-11-09）：拔环之后只要攥着保险握片就不计时，出手握片弹开才开始倒计时，
  所以手上不会炸，也没有"攥久了空爆"。原来的"拉环就开始倒计时、攥满在手里炸"去掉了（#1）。真实手雷（如 M67）就是这样：握片被手压着击针打不下去，松手握片弹开引信才燃烧。
- **NPC 丢雷像人一样判断，手雷按露出部位算伤害**（2026-11-10，负责人要求）：NPC 推算玩家躲到了哪、听枪声、出手前预演，丢不准不丢；
  爆炸伤害看头、胸、腿露出几处，不再"只看眼睛一条线"。引信出手就开始算（飞行时间算在内），手雷从 3 秒改成 2 秒：3 秒时雷落地后还要躺 1–2 秒，对方有充足时间跑开（#5）。细节见 `architecture.md` 的"各系统要点"。
- **经济系统**（2026-11-09，负责人要求）：起因是对决里一直赢就一直不补投掷物。打死敌人按最后一击给赏金（爆头 / 普通 / 手雷），
  钱有上限，回到这条命的出生点买枪、子弹和投掷物。数值在 `config.js` 的 `economy`。
  **子弹限量**（#7，负责人定的）：每条命只有枪里一个弹匣，多的花钱买（$2 一发，最多 3 个弹匣）；开局和重生钱至少补到 `startMoney`（够买主武器，#90），
  免得连着被杀的一方一直没钱。NPC 的配置和玩家一致（同样只有一个弹匣、一枚手雷），但 NPC 没有经济买不了，打空就跑开。
  不卖血和护甲（护甲见 #83）；训练场购买免费（#90）。燃烧弹单独做（#63）。
- **换弹不显示文字**（2026-11-09）：去掉准星下方的"换弹中…"，靠完整的换弹动作（抽弹匣、拿新弹匣、拍实、空枪拉机柄）和弹药数下的进度细线表达。
  打空自动换弹，切枪中止（#1）。
- **面向边做边学的开发者。** 代码注释、文档都用中文；结构上追求"改一个参数就能看到变化"，所以数值集中在 `config.js`。

## 技术选型

- **纯浏览器、零构建、无后端。** three.js r149，脚本按 `index.html` 的顺序直接加载，全局命名空间 `Game.*`。
  不引入打包工具和框架，打开文件就能读懂。
- **本地运行用 `start.sh`（python http.server）**，不支持双击 `index.html`：浏览器禁止 `file://` 加载 glb 模型。
  直接双击时 NPC 会退化成方块小人（BlockModel），游戏仍能玩。
- **资源用 CC0 / MIT / CC BY 4.0**（另外：付费账号用 Tripo 生成的底模，见下面 Blender 那条，#72），来源登记在 `assets/LICENSES.md`。（2026-11-06 加入 CC BY：写实的枪模型大多是 CC BY，只用 CC0 几乎找不到）
  CC BY 要署名：`LICENSES.md` 里写作者、原作链接、授权、做过哪些修改，首页底部的"素材来源与署名"链接指向它。
  不用 CC BY-NC（禁止商用）、CC BY-ND（禁止修改）、CC BY-SA（改了要用同样授权发布）。
- **音效混合**（负责人定，#45）：枪声、换弹、手雷 / 闪光爆炸用真实录音（合成的"电子味"太重），命中、击杀、购买这类提示音和烟雾嘶声保持合成（提示音本来就要"干净"）。
  录音点开始后后台下载、不卡开始按钮，下完前用合成声顶着；全部剪成小 mp3（共约 200 KB）。不加脚步声、子弹擦耳之类的新音效，等负责人提。
- **没有原作链接的模型写"同事提供、不登记原作链接"**（2026-11-11，负责人定）：授权符合要求就能进游戏，`LICENSES.md` 照 `m4.glb` 那一行写（#42，来源 #14）。
- ~~枪模、手、手雷、卡车都用基础几何体拼，贴图用 Canvas 画~~（2026-11-06 废止，见下一条）。
- **枪械、人物、地图一律用 Blender 建模，导出 glb**（2026-11-06）。不再用 JS 几何体拼模型、Canvas 画贴图。
  起因：几何体加 Canvas 贴图做出来的手臂和枪很假，调参数也救不回来。逼真度靠真实建模和 PBR 材质（颜色、法线、粗糙度、金属度、AO）。
  - 做法：Python 脚本驱动 Blender 无头模式建模、做材质、烘焙，渲染预览图给负责人确认后再导出。
    建模脚本和 `.blend` 母版放 `assets-src/`，可重复生成；产物经 `/glb` 压缩后放 `assets/`。
  - 外部素材（Poly Haven、ambientCG 的材质，CC0 / CC BY 模型）可以作为起点，授权规则见上面一条。
    下载的原始文件也放 `assets-src/` 当母版，加工脚本从它开始。第一个例子：`assets-src/models/gun/ak47.py`。
  - JS 只负责加载模型和玩法逻辑。现有的 `gunmodel.js`、`textures.js` 等代码生成的模型和贴图逐个替换，替换前照常可用。
  - 例外：枪口火焰、弹孔、血迹、粒子这类运行时特效，以及 UI，仍然用代码做。
  - 地图的碰撞盒、出生点、巡逻点怎么从 Blender 里出，做第一张 Blender 地图时定，定了补到 `maps.md`。
  - **Tripo（AI 生成 3D）只出底模**（2026-11-12，负责人定，#72）：照参考图或文字生成的模型当起点，
    必须进 Blender 修整（减面、修拓扑、统一比例和朝向、换成项目的 PBR 材质）、渲染预览图给负责人确认，才能进 `assets/`，不直接用。
    起因：生成的模型面数、贴图和风格不受控，和现有的枪、人物、地图放在一起会不统一；当底模能省掉从零建模的大部分时间。
    授权：负责人查过 Tripo 官方条款，付费账号生成的模型可以用于商业游戏，所以虽然不是 CC0 / CC BY，也可以进游戏，按 `LICENSES.md` 的规则登记。
    生成按积分计费，花积分前先报价、负责人同意再跑。做法见 `art-sources.md` 的"用 Tripo 生成底模"和 `/tripo` skill。
- **NPC 死亡用自己写的 Verlet 布娃娃**（`ragdoll.js`），不引入物理引擎。
- **多地图按需加载**：每张地图的资源单独放，选了哪张才下载哪张，首次下载体积保持在"引擎 + 一张图"。

## 开发和部署

- **开发机**（2026-11-05）：GCP 实例 4 核 32G，x86_64，无 GPU、无显示器。WebGL 靠 SwiftShader 软件渲染，
  截图和报错可信，帧率不可信。真实帧率和手感要在有显卡的电脑上测。
- **暂不支持 Safari**，所以没有为测试租云 Mac。需要真实帧率时优先按小时开 GPU 主机，不包月。
- **工具链走命令行**（Playwright、gltf-transform、Blender 无头模式），Claude Code 通过 `.claude/skills/` 调用，见 `tools.md`。
- **线上**（2026-11-04）：https://game.lightup.host，跑在开发机上，借用 paseo-relay 项目的 Caddy 按域名分流。
  relay 是另一个在线服务，不能中断，所以游戏不单独占 80/443。细节见 `deploy.md`。
- **分支开发完一律并入 `main`，从 `main` 部署；分支不删除，保留历史**（2026-11-06），见 `workflow.md`。
  起因：v0.10、v0.11 都从功能分支部署过，线上一度比 `main` 新，从 `main` 部署就会回退。
- **每个上线的版本都打 tag**（2026-11-09，原来只给大版本打）：回滚靠 tag，v0.10 ~ v0.20 一度都没有 tag，回滚无处可回。
  `ship.sh --tag` 部署成功后自动打，已发布的 tag 不移动。见 `workflow.md` 的"版本号"。
- **项目进展用 GitHub 管**（2026-11-10，负责人提的，#27）：需求、bug、待确认、想法用 Issue，一个版本一个 Milestone，合并走 PR，上线建 Release。
  边界：讨论、过程、验证记录留在 issue 和 PR；仓库里的文档只写现状，按模块组织（系统怎么工作、为什么这样做、坑、规则），
  写到哪条结论就带上 `（#N）`，读者想看来龙去脉再去 GitHub。拉下仓库看文档就能接手，不用翻 issue。
  PR 用合并提交、不 squash、不删分支；不用 Actions、分支保护、PR 审核（一个人开发，PR 只留记录）（#27）。
  仓库是公开的，GitHub 上不贴录下的数据和敏感信息。见 `workflow.md` 的"GitHub 上管什么"。
- **issue 由负责人在会话里指定，Claude 不定时拉取**（2026-11-11，#58）：原来开发机每 30 分钟查一次打了 `交给Claude` 的 issue，
  无人值守地做（#29、#37）；负责人实践下来觉得效果不理想，改成负责人新开会话说"ISSUE51"，Claude 按同样的流程做和跟进，
  驱动方是负责人，不是 Claude 挑。流程在 `/issue` skill，见 `workflow.md`。定时器、`tools/autopilot/` 已删除（历史见 #29、#58）。
  仍然在开发机上做、不用 GitHub Actions（工具链都在开发机）；暂不做预览站点（项目还没面向玩家）。

- **开发接口 `server/api.py`**（2026-11-09，#2）：为开发者模式加了一个只给开发用的小服务（密码换令牌、接收上传），
  线上是 `fps-api` 容器，`fps-game` 的 Caddy 把 `/api/*` 转过去，relay 的配置不动。**游戏本身仍然不需要后端**，接口挂了照样能玩。
  以后的后台（玩家账号、按玩家开开发者模式）也加在 `/api/` 下（#16）。见 `devmode.md`。
- **真机问题靠开发者模式录数据**（2026-11-09）：不为开发机加 GPU。动画和手感的问题主要是"截图看不到连续动作"，
  加了 GPU 也看不到负责人的显示器刷新率和真实手感；所以让负责人在自己电脑上录每帧数据（和可选的画面）上传，开发画曲线分析。
- **采集数据只限游戏本身**（2026-11-10，负责人定的隐私规则，#4）：开发者模式和以后的任何日志、后台只收游戏画面、帧率、游戏运行数据和设置，
  **不收 IP 地址和浏览器环境**（浏览器、系统、显卡、屏幕等），数据搜集最小化；以后调试真需要，要在玩家同意的前提下再收。登录限流的 IP 计数只在内存里。见 `devmode.md` 的"隐私"（以后征得同意再收见 #17）。
- **Claude 在 GitHub 上用独立的机器账号 primorigin**（2026-11-11，#46）：提交、PR、评论能看出是谁做的，负责人也能收到通知；
  用普通 GitHub 账号，不用 GitHub App（要管私钥、每小时换 token，个人项目太重）；推送走 SSH（负责人定的）。
  见 `tools.md` 的"GitHub 账号"。
