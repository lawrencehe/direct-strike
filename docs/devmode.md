# 开发者模式：真机数据和画面

开发机没有显卡，只能看逐帧截图，看不到连续的动作，也测不了真实帧率。开发者模式在负责人（或指定玩家）的电脑上
录下每一帧的真实数据，需要时也录画面，上传到服务器；开发用分析脚本把它画成曲线、找卡顿、对着视频帧看（#2）。

为什么不是给开发机加 GPU：动画和手感的问题主要是"开发只看得到单张截图"，加了 GPU 也看不到负责人显示器的刷新率和真实手感，
而且这台机器上还跑着线上站点和 relay，换机型要停机。

负责人定的要求：打开开发者模式**不能让游戏变卡**（数据不必实时落盘）；画面切片存、分辨率码率不用高；
要输入固定密码、服务器校验通过才能打开；服务器数据目录上限 10 GB。以后的后台（玩家登录、数据管理、按玩家开开发者模式）加在 `/api/` 下（#16）。

## 怎么用（玩的人）

1. 首页 → 设置 → 最下面"开发者"，输入密码，点"解锁"。解锁后开发者模式自动打开，令牌在浏览器里存 30 天。
   密码在服务器的 `~/direct-strike-data/api.env`（`DEV_PASSWORD`），本地 `start.sh` 没有这个文件时密码是 `dev`。
2. 进入战斗照常玩。左上角会多一个小浮层：帧率、帧时间、最慢 1% 的帧时间、最近 160 帧的柱状图（红色 = 卡顿）。
3. **觉得哪一下不对，马上按 F8 打个标记**（键在 `config.dev.markerKey`）。开发先看标记前后几秒。
4. 要看画面上的问题（穿模、手的姿势、贴图），在"开发者"里打开"录制画面"，再复现一次并按 F8。
   录画面要拷画面、编码视频，会占一些显卡；如果明显变卡，它会自动关掉并提示。负责人真机试过：有一些影响，在预期内（#9）。
   **快捷键 ⇧⌘=（Windows：Ctrl+Shift+=）在哪都能直接打开"开发者"一栏**：战斗中按会先暂停，全屏 + 锁鼠标时也能用（负责人真机确认，#12）；键在 `config.dev.panelKey`。
5. 按 Esc 暂停 →"开发者数据"（或按快捷键、回首页的设置页），看统计，点"上传"。上传成功会显示一个编号，例如 `20261109-213000-a3f9c1`，
   把编号告诉开发。上传失败可以先"下载到本地"（只有帧数据）。

只录战斗中（鼠标锁定时）的帧，暂停、菜单不录，所以暂停下来看面板、上传不会把战斗数据挤掉。
内存里保留最近 60 秒（`config.dev.seconds`，按 250 帧/秒预留，帧率更高时保留的秒数短一些），画面保留最近 30 秒（6 片 × 5 秒）。

## 怎么分析（开发）

```bash
node tools/devlog/analyze.mjs --list          # 所有上传：编号、版本、模式、时长、帧率、标记数、视频片数
node tools/devlog/analyze.mjs                 # 最新一次
node tools/devlog/analyze.mjs <编号> --at 12.5,30 --around 2   # 额外看某几个时刻，前后 2 秒
node tools/devlog/analyze.mjs devlog-xxx.json.gz              # 分析"下载到本地"的文件（或任意目录）
node tools/devlog/analyze.mjs <编号> --no-video                # 不拆视频帧，快一些
```

输出在 `tools/out/devlog/<编号>/`：

| 文件 | 内容 |
|---|---|
| `report.md` | 画布大小、帧时间统计、最慢的几帧（当时在做什么、CPU 花了多少）、枪模跳变、换弹时长、标记、事件统计 |
| `overview.png` | 整段的帧间隔，橙色竖线是标记 |
| `marker-N.png` / `at-T.png` | 标记 / 指定时刻前后的曲线：帧间隔和 CPU、枪模位置、枪模旋转、动作进度（换弹 / 切枪 / 后坐 / 投掷）、左手位置、鼠标和移动速度。每帧一个点，看得出帧率 |
| `jump-N.png` | 枪模跳变最大的几处，前后 1.5 秒 |
| `marker-N-video.jpg` | 标记前 0.5 秒到后 0.6 秒的视频帧，每 0.1 秒一张，橙框是那一刻（录了画面才有） |

读报告的要点：

- **帧间隔中位数 ≈ 显示器刷新率**（16.7ms = 60Hz，6.9ms = 144Hz）。在高刷新率显示器上才出现的问题，要按这个帧率去想。
- **卡顿时看 CPU 列**：CPU 时间小而帧间隔大，是卡在显卡或浏览器合成（画面太重、垃圾回收以外的原因）；CPU 时间大是卡在脚本。
  `longtask` 事件是浏览器报告的超过 50ms 的任务（只有 Chrome 系有）。
- **枪模跳变**：按 60Hz 折算后，一帧之内枪模移动超过 1.5cm、转动超过 3.4°、左手移动超过 3cm（开枪那一帧除外）。
  动作本该连续的地方出现跳变，玩起来就是"闪一下"。
- 曲线里的位置和旋转减去了窗口中位数，所以纵轴是"偏离平常多少"。

分析脚本用 Playwright 自带的 Chromium 画图和拆视频帧，不另装 ffmpeg。MediaRecorder 录的 webm 没有索引、跳转不准，
所以拆帧是顺序播放，用 `requestVideoFrameCallback` 给每个目标时刻留最近的一帧；`file://` 的视频画到 canvas 上算跨源，启动参数加了 `--allow-file-access-from-files`。

## 数据格式

上传目录 `~/direct-strike-data/devlogs/<编号>/`：

- `meta.json`：服务器写的，收到的时间和客户端给的摘要（版本、帧数、时长、帧率、标记数、视频片数、模式；别的键服务器丢掉）。
- `frames.json.gz`：帧数据，见下。
- `seg-NNN.webm`：画面切片，每片 5 秒，每片都能单独播放（960 宽、30fps、1.5Mbps，参数在 `config.dev.video`）。

`frames.json.gz` 解压后是一个 JSON：

| 键 | 内容 |
|---|---|
| `format` / `formatVersion` | `direct-strike-devlog` / 1 |
| `meta` | 版本、录制时间、画布尺寸和像素比、是否全屏、模式、选的枪、按键绑定、当时完整的 `Game.Config`（v0.21 的旧数据还有浏览器、显卡等，见"隐私"） |
| `stats` | 浏览器端算的帧时间统计 |
| `recordCost` | 录制本身每帧花了多少微秒（平均、最大） |
| `channels` / `weapons` / `actions` | 通道名；`weapon` 通道的下标对应的武器；按键位掩码每一位对应的动作 |
| `t` | 每帧的时间（毫秒，页面计时器，和事件、视频同一个基准） |
| `data` | 按通道分列，`data.vmY[i]` 是第 i 帧枪模的 y。没有值是 `null` |
| `events` | `{ t, type, v }`：`fire`（v = 剩余子弹）、`reloadStart`（v = 1 空枪）、`reloadEnd`、`reloadCancel`、`switch`（v = 新武器下标）、`jump`、`land`（v = 落地速度）、`throw`、`hurt`（v = 伤害）、`death`、`respawn`、`marker`（v = 第几个）、`lock`、`unlock`、`longtask`（v = 毫秒）、`videoSegment`（v = 片号） |
| `video` | `{ file, t0, t1, bytes }`：每片视频对应的时间段 |

通道（定义在 `js/devlog.js` 开头的 `CH`）：

| 通道 | 含义 |
|---|---|
| `dtRaw` / `dt` / `work` | 真实帧间隔、游戏用的帧间隔（截到 50ms）、这一帧 CPU 花的时间（逻辑 + 提交渲染），毫秒 |
| `lookX` / `lookY` | 这一帧鼠标移动（像素） |
| `keysDown` / `keysPressed` | 按住 / 刚按下的动作，位掩码，第 k 位是 `actions[k]` |
| `posX..Z` / `velX..Z` / `yaw` / `pitch` / `recoilPitch` | 玩家位置、速度、视角、后坐力上抬 |
| `onGround` / `crouchT` / `bobPhase` / `health` | 着地、下蹲进度、走路晃动相位、生命 |
| `weapon` / `switchPhase` / `switchT` | 当前武器、切枪阶段（0 无 / 1 收 / 2 掏）、切枪计时 |
| `reload` / `reloadEmpty` / `ammo` | 换弹进度 0~1（没在换弹 -1）、是否空枪换弹、子弹 |
| `throwState` / `holdT` / `swingT` | 投掷（0 无 / 1 攥着 / 2 挥臂）和计时 |
| `kick` / `bloom` / `swayX` / `swayY` | 后坐动画、散布、枪模晃动 |
| `vmX..Z` / `vmRX..Z` | 枪模（或手雷）在枪模摄像机里的位置、旋转 |
| `lhX..Z` / `magY` / `magZ` | 左手、弹匣在枪坐标系里的位置（拿手雷时为空） |

加通道：在 `CH` 里加名字，在 `sample()` 里写值。分析脚本按名字读，旧数据没有的通道是 `undefined`，用之前判断一下。

## 隐私

**只收游戏本身的数据**：游戏画面、帧率和帧时间、游戏运行数据（输入、玩家和武器状态、事件）、游戏设置。
**不收**玩家的 IP 地址和浏览器环境（浏览器型号和版本、操作系统、显卡型号、CPU 核数、内存、屏幕分辨率、网址）。负责人 2026-11-10 定的规则：
**数据搜集最小化**，以后加通道、加字段都按这条，拿不准算不算"游戏相关"的先问（#4）。
以后调试确实需要设备信息（比如显卡型号）时，**要先征得玩家同意再收**（例如上传前明确勾选），不能默认收（#17）。

- 帧数据的 `meta` 只有版本、画布尺寸和像素比、全屏、模式、装备、按键、`Game.Config`。显示器刷新率不直接读，从帧间隔中位数推。
- 服务器的 `meta.json` 不记 IP，客户端摘要按白名单（`server/api.py` 的 `CLIENT_KEYS`）留键，旧版页面多传的键丢掉。
- 接口日志（`docker logs fps-api`）只有时间和请求，没有 IP。
- 登录限流要按 IP 计数（防止猜密码；不按 IP 就只能全局限流，别人乱试会把负责人也锁住），这个计数**只在内存里**，10 分钟前的记录随时清掉，不写日志、不落盘，重启就没了，不算"搜集"。
- 视频只录 3D 画面（不含 HTML 界面），帧数据里的按键是游戏动作的位掩码，不是键盘原始输入。
- 代价：分析时不知道对方的显卡和浏览器。帧率、卡顿、CPU 时间照样能看；真要知道显卡，让负责人口头说。

## 性能设计

开着它不能让游戏变卡：

- 每帧只往打开时一次性分配好的 `Float32Array` 里写数字（约 3MB），**不新建任何对象**。新建对象多了会触发垃圾回收，那才是"偶尔卡一下"的常见原因。
  按键状态在键盘、鼠标事件里算好位掩码，不在每帧去 `Set` 里查；three.js 的 `Euler` 读内部字段 `_x`，不走 getter（getter 没内联时返回小数要装箱）。
- 浮层每 0.25 秒刷新一次；统计、整理 JSON、压缩、上传只在打开面板和点按钮时做（那时游戏暂停）。
- 关着的时候 `main.js` 每帧只多一个判断。
- 事件（开火 = 子弹变少、换弹开始 / 结束、切枪、落地……）从每帧状态的变化推出来，不改武器和玩家的代码，只在 `main.js` 挂 `sample` / `afterRender` 两个调用。
- 面板上的"录制耗时"就是 `sample()` 实测的耗时。开发机（慢 CPU）上约 10µs/帧，`tools/tests/devlog.mjs` 用 CDP 的采样堆分析器确认 2 万帧零分配。
- 录画面是另一回事：要在每帧渲染完立刻把画面缩小拷到一块 2D 画布（晚了 WebGL 画布就清空了），浏览器再按 30fps 编码。
  做法：渲染后立刻把 WebGL 画布缩小拷到 2D 画布，对 2D 画布 `captureStream(30)` 自动采样；每 5 秒换一个录制器，所以每片都能单独播放。
  手动 `requestFrame` 的写法在无头环境录出来是空的，不用。
  开销取决于显卡，开发机测不了，所以默认关，并且有保护：出现超过 1 秒的帧、2 秒内 3 帧超过 0.2 秒、或者战斗中 1.5 秒没出帧
  （用定时器查：出帧停了，每帧的检查就跑不到），就自动关掉。负责人真机试过开销在预期内（#9）。

## 服务器

`server/api.py`，只用 Python 标准库。线上跑在 `fps-api` 容器里（见 `deploy.md`），本地由 `start.sh` 启动（同时出静态文件）。

| 接口 | 作用 |
|---|---|
| `POST /api/dev/login` `{password}` | 密码对了返回 `{token, exp}`。同一 IP 10 分钟内输错 10 次就拒绝 |
| `GET /api/dev/session` | 令牌还有没有效。页面启动时查一次，失效（比如改了密码）就自动退出开发者模式 |
| `POST /api/dev/uploads` `{meta}` | 新建一次上传，返回编号 |
| `PUT /api/dev/uploads/<编号>/<文件名>` | 放一个文件。文件名只允许 `frames.json.gz`、`seg-NNN.webm/mp4`；单个最大 25MB；新建 1 小时后关闭 |
| `GET /api/health` | 健康检查 |

- 令牌是 `base64(JSON {sub, exp}).HMAC`，签名的钥匙由 `API_SECRET` 和密码一起算出来，**改密码就让所有旧令牌失效**。
  `sub` 现在固定是 `dev`；以后做后台（玩家账号、按人开开发者模式）时换成玩家 id。
- 数据目录总大小超过 `DATA_QUOTA_GB`（默认 10）就从最旧的上传开始删。
- 改密码：改 `~/direct-strike-data/api.env` 的 `DEV_PASSWORD`，然后 `docker restart fps-api`。

### 在服务器上看数据和密码

```bash
grep DEV_PASSWORD ~/direct-strike-data/api.env            # 现在的密码
ls -lt ~/direct-strike-data/devlogs | head                # 最近的上传（编号就是目录名）
du -sh ~/direct-strike-data/devlogs                       # 占了多少（上限 DATA_QUOTA_GB）
cat ~/direct-strike-data/devlogs/<编号>/meta.json          # 什么时候传的、哪个版本、多长
docker logs --tail 50 fps-api                             # 接口日志（登录、上传、报错；不含 IP）
```

不想要的上传直接删目录即可，服务器不另记索引。

## 常见问题

| 看到的提示 / 现象 | 原因和办法 |
|---|---|
| "密码不对" | 密码以服务器 `api.env` 为准，改过密码要用新的 |
| "输错太多次，过 10 分钟再试" | 同一 IP 10 分钟内输错 10 次（只在内存里计数），等 10 分钟；或 `docker restart fps-api` 清掉计数 |
| "服务器没有开发接口（本地请用 start.sh 启动）" | 本地用别的方式（`python -m http.server`、VS Code 插件）出的页面，没有 `/api/`；线上出现说明 fps-api 没起来，见 `deploy.md` 的"开发接口排查" |
| 本来解锁了，打开页面变回没解锁 | 令牌失效：过了 30 天，或服务器改了密码 / `API_SECRET`。重新输密码 |
| "录画面让游戏明显变卡，已自动关闭" | 这台电脑录画面太吃力，帧数据不受影响照常录。要录画面可以先把画质调低再试 |
| "上传失败：上传不存在或已关闭" | 一次上传建好 1 小时后关闭（例如暂停着放了很久），重新点"上传"即可，会新建一个编号 |
| "上传失败"，其他原因 | 先"下载到本地"保存帧数据（`devlog-*.json.gz`），把文件发给开发，`node tools/devlog/analyze.mjs <文件路径>` 直接分析；画面只能上传 |
| 统计里帧数是 0 | 只录战斗中（鼠标锁定时）的帧，进一局玩一会儿再看 |
| 分析脚本说没有视频 | 没开"录制画面"，或者录画面被自动关掉了；`report.md` 的事件统计里看有没有 `videoSegment` |

## 限制

- 无头 Chromium + 软件渲染（开发机）录 WebGL 画面会卡住出帧、录出来是空的，所以测试只覆盖录画面的流程和自动关闭保护，
  真实画面要在有显卡的电脑上看。分析脚本的拆帧用一段 2D 画布录的视频验证过（时间对得上，误差 < 0.03 秒）。
- 视频只有 3D 画面，没有 HUD（准星、弹药是叠在上面的 HTML）。
- Safari 不支持（游戏本身也没测过）。
